System prompt design

The advisor is instructed to treat every vendor claim as unproven until the user names actual evidence: a study, an audit, a named certification. Five fixed dimensions (clinical safety, data governance, bias and validation, integration risk, commercial terms) keep the conversation from wandering into generic Q&A. The model returns one structured JSON object per turn, a conversational reply plus a ledger update plus an optional verdict, so the interface never has to guess at intent from prose.

  • Role and scope are fixed first, before tone, so the model cannot be talked into approving without evidence
  • Status vocabulary (claimed, documented, missing, unexamined) is defined explicitly to keep grading consistent turn over turn
  • Edge cases (pasted marketing copy, demand for instant approval, out of scope legal questions) are handled in the prompt, not patched in the UI

UI decisions

The layout borrows the shape of a deposition room rather than a generic chat window: a transcript on the left, a living evidence ledger on the right that fills in as the conversation earns it, and a verdict that arrives as a stamped case decision rather than a percentage score. The stamp only appears once the model actually issues a call, so it cannot be mistaken for a running score.

  • Ledger rows are colour coded by evidentiary strength, not by sentiment, so gold means claimed-not-proven rather than good
  • Three HealthNexus theme variants and full Arabic RTL mirroring apply to every chrome element, keeping the tool consistent with the rest of the portfolio
  • The composer intentionally has no reset button; a diligence record is not meant to be discarded mid-session

Extending this tool

This build is single turn request and response with no memory beyond the visible transcript. The next layer of work turns it into a durable governance artifact rather than a one-off conversation.

  • Tools: let the advisor call a real vendor-document search or a clinical evidence database instead of relying only on what the user types
  • Memory: persist the ledger per vendor across sessions so re-engaging with the same vendor six months later starts from the prior record, not zero
  • Multi-step workflow: route a "conditions" verdict into a tracked follow-up list with owners and due dates, so a soft approval cannot quietly become a full approval without the conditions being closed
